0 システム概要

FISC-QAv2は、金融情報システムセンター（FISC）の金融機関向けアンケートに対し、社内ドキュメントを根拠としてAIが回答案を自動生成するシステムです。

入力

  • FISCアンケート回答票（Excel / Word）
  • 社内ポリシー・過去回答・設計書（KB: 数百ファイル対応）

出力

  • 回答済みExcel / Word（元ファイルに回答を記入）
  • 回答・根拠・信頼度スコア
  • 過去回答DB・共通回答DBへの自動蓄積

5.1 Agent 0: Orchestrator（司令塔）

ソースコードsrc/orchestrator.py
LLM依存不要 — 純粋な制御ロジック
入力質問票Excelパス, KBディレクトリ, Config
出力出力Excelファイルパス

責務

  • パイプライン制御: 5段階処理を順序実行（Index → Route → Read → Review → Output）
  • 過去回答の再利用判定: Router結果 + Indexer更新情報から、関連KBが未更新なら過去回答を採用（LLMスキップ）
  • Reader並列実行: ThreadPoolExecutorでFan-out/Fan-in。全Readerが同時実行
  • リトライ制御: 指数バックオフで最大3回リトライ。全失敗時は「未回答」+LOW信頼度で埋める
  • 結果集約: 全Readerの回答を dict[int, Answer] にマージ

5.2 Agent 1: Indexer（資料整理係）

ソースコードsrc/indexer.py
LLM依存オプション — LLMなし: ローカル500文字要約のみ
入力KBディレクトリ, 前回インデックス (optional)
出力list[IndexEntry]

責務

  • ファイル走査: KB配下を再帰走査しPDF/DOCX/XLSX/テキストを列挙
  • 要約抽出: PDF先頭2ページ、DOCX見出し優先、XLSX全行、テキスト先頭50行から500文字要約
  • トークン数推定: ヒューリスティック（日本語2文字/token、英語4文字/token）
  • 変更検知: mtime比較で updated フラグ設定
  • キャッシュ: .fisc_index_cache.json に保存/読み込み

5.3 Agent 2: Router（振り分け係）

ソースコードsrc/router.py
LLM依存オプション — LLMなし: 静的キーワードマッチ（12カテゴリ）
入力list[Question], list[IndexEntry], token_budget
出力RoutingResult (list[ReaderAssignment])

責務

  • LLM動的ルーティング: インデックス+質問をLLMに渡し、各質問に1-3ファイル割当
  • 静的フォールバック: _KEYWORD_MAP（12カテゴリ） + _CATEGORY_HINTS
  • ビンパッキング: 質問+ファイルを token_budget_per_reader（デフォルト80,000）に収まるようReaderに分配
  • Reader割り当て生成: reader_id=A/B/C..., questions, files, estimated_tokens

5.4 Agent 3: Reader（回答担当）

ソースコードsrc/reader.py
LLM依存必須 — LLMなしでは動作不可
入力reader_id, list[Question], ファイルパス, KB base dir, API key, model
出力list[Answer]

責務

  • KB全文読み取り: PDF（PyMuPDF/フォールバック）、DOCX、XLSX、テキスト
  • 回答生成: KB全文+質問リストをLLMに投入（max_tokens: 16,384）
  • 応答パース: 3段階フォールバック（直接parse → コードブロック抽出 → 括弧深度マッチング）
  • 切断回復: finish_reason="length" 時に閉じ括弧補完で部分回答救済
  • 欠損補完: LLM応答に含まれなかった質問を「回答不可候補」+LOW信頼度で埋める
Reader はシステムの核心。複数インスタンスが並列実行される（Reader A, B, C...）。各Readerは独立して動作し、Routerが割り当てたファイルセットのみを読む。

6 ユーザ操作説明

システム利用の標準フローを説明します。

6.1 初回セットアップ

  1. ログイン: メールアドレスを入力してログイン（ホワイトリスト登録が必要）
  2. 銀行登録: 「銀行管理」画面で対象銀行を登録（名前・コード）
  3. QAファイル定義: 銀行ごとに質問票のフォーマットを定義
    • ファイル形式（Excel / Word）
    • 質問列・回答列の列番号
    • ヘッダー行・データ開始行
    • 回答形式（自由記述型 / 選択肢+備考型 / 判定型）
  4. 過去回答アップロード（任意）: 銀行詳細画面から過去回答票をアップロード。Q&Aペアが自動抽出されDBに蓄積
  5. 共通回答登録（任意）: 銀行横断で使える共通回答テンプレートを登録

6.2 回答作成フロー（5ステップ）

1. Upload
→
2. Past Match
→
3. Common Match
→
4. AI Generate
→
5. Finalize

Step 1: 質問票アップロード

  1. 「セッション」→「新規セッション」
  2. 銀行を選択
  3. QAファイル定義を選択（あれば）
  4. 質問票ファイル（Excel/Word）をアップロード
  5. 質問が自動抽出され、Step2へ遷移

Step 2: 過去回答マッチング

  1. 「マッチング実行」をクリック
  2. システムが過去Q&AとAI類似度照合
  3. マッチ結果をテーブルで確認
  4. 各質問の過去回答を「採用」or「却下」
  5. 「確定してStep3へ」をクリック

Step 3: 共通回答マッチング

  1. Step2で未解決の質問のみ表示
  2. 「マッチング実行」（LLMで共通回答DBと照合）
  3. マッチ結果を「採用」or「却下」
  4. 全解決済みならスキップ可能
  5. 「確定してStep4へ」

Step 4: AI回答生成

  1. まだ未解決の質問について「生成を開始」
  2. マルチエージェントパイプラインが自動実行
  3. SSEでリアルタイム進捗を確認
  4. 完了後「Step5: 最終確認へ」
  5. エラー時は再試行 or スキップ可能

Step 5: 最終確認・エクスポート

  1. 全質問の回答一覧を確認
  2. ソース別に色分け表示（過去/共通/AI/手動/未回答）
  3. 各回答を編集可能（鉛筆アイコン）
  4. 共通回答DBへの追加をチェック
  5. 「確定して蓄積」→ 過去回答DBに自動蓄積
  6. 「エクスポート」→ 元ファイル形式でダウンロード

自動蓄積の仕組み

  • Step5で「確定して蓄積」を押すと:
  • 全回答が past_qa テーブルに自動蓄積
  • 「共通回答DBに追加」チェック分は common_answers にも追加
  • 次回セッションのStep2/Step3で自動的に活用される
  • 使えば使うほど精度が上がる仕組み
