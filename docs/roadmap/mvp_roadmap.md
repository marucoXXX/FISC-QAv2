# MVP 開発ロードマップ
**プロジェクト:** FISCセキュリティアンケート自動回答システム  
**Version:** 1.0  
**最終更新:** 2026-03-07  
**開発方式:** AIペアプログラミング（Claude）  
**MVPゴール:** 社内デモ・動作確認

> **FISCとは：** 公益財団法人 金融情報システムセンター（The Center for Financial Industry Information Systems）。1984年設立・内閣府所管。「金融機関等コンピュータシステムの安全対策基準・解説書」（約300項目）を策定し、毎年「金融機関アンケート」として金融機関のIT利活用状況・安全対策実施状況を調査している。銀行・保険・証券・クレジット会社などが回答対象。

## PHASE 1 ── テストデータ準備

> ゴール：コーディング前に、テストで使える全ファイルを揃える

### STEP 1-1｜アンケート質問表（Excel）の作成
- FISCの「金融機関アンケート回答票」を想定した架空のExcelを作成
- 質問数：10〜15問（Yes/No系・記述系・選択系を混在させる）
- 形式：`questionnaire_sample.xlsx`
- カラム：`No.` | `質問テキスト` | `回答欄（空白）`
- 質問例：パスワードポリシー、MFA、暗号化、DR対応、脆弱性診断、インシデント対応、アクセスログ管理、外部委託先管理など（FISC安全対策基準の項目を参考に設計）

### STEP 1-2｜セキュリティポリシー文書（PDF）の作成
- 架空会社の情報セキュリティポリシーをPDFで作成
- 格納先：`/knowledge_base/policies/`
- ファイル名：`security_policy.pdf`
- 含める内容（アンケートの答えが引けるように設計）：
  - パスワードポリシー（文字数・有効期限・複雑さ要件）
  - アクセス制御ポリシー
  - MFA（多要素認証）の適用範囲
  - データ暗号化方針
  - インシデント対応手順の概要

### STEP 1-3｜過去のアンケート回答実績（Excel）の作成
- 架空の過去回答を2〜3件分作成
- 格納先：`/knowledge_base/past_answers/`
- ファイル名：`past_answer_2024.xlsx` など
- カラム：`No.` | `質問テキスト` | `回答` | `根拠`

### STEP 1-4｜設計・運用ドキュメント（Word or PDF）の作成
- 格納先：`/knowledge_base/system_docs/`
- ファイル名：`system_overview.pdf`
- 含める内容：
  - インフラ構成の概要（クラウド利用状況、サーバー構成）
  - バックアップ・DR対応方針（RPO/RTO目標）
  - 脆弱性診断の実施状況
  - ログ・監査の概要

### STEP 1-5｜テストデータの整合性確認
- アンケートの質問と、knowledge_base内ドキュメントの内容が対応しているか確認
- 高信頼度で答えられる質問（8問）・低信頼度になる質問（2〜3問）を意図的に設計する
- フラグ（🚩）が正しく出るかを後工程でテストするため

## PHASE 2 ── バックエンド実装

> ゴール：CLIまたはAPIで、Excelを受け取りClaude回答JSONを返せる状態にする

### STEP 2-1｜プロジェクト構成のセットアップ
```
/project
  ├── knowledge_base/
  │   ├── policies/
  │   ├── past_answers/
  │   └── system_docs/
  ├── backend/
  │   ├── main.py          # FastAPI エントリポイント
  │   ├── doc_loader.py    # ドキュメント読み込みモジュール
  │   ├── excel_parser.py  # Excel 質問パースモジュール
  │   ├── claude_client.py # Claude API 呼び出しモジュール
  │   └── excel_writer.py  # Excel 出力モジュール
  ├── frontend/            # PHASE 3 で追加
  └── requirements.txt
```

### STEP 2-2｜ドキュメント読み込みモジュール（doc_loader.py）
- `/knowledge_base/` 以下を再帰的に走査
- PDF → `PyMuPDF`、Word → `python-docx`、Excel → `openpyxl` でテキスト抽出
- ファイル名をヘッダーとして付与した結合テキストを返す
- テスト：ファイルが正しく読み込まれ、テキストが取得できるか確認

### STEP 2-3｜Excelパースモジュール（excel_parser.py）
- `openpyxl` で質問Excelを読み込み
- `[{ "id": 1, "text": "質問テキスト" }, ...]` 形式のリストを返す
- テスト：STEP 1-1 で作成したサンプルExcelで動作確認

### STEP 2-4｜Claude API 呼び出しモジュール（claude_client.py）
- モデル：`claude-sonnet-4-5`
- 入力：質問リスト + ドキュメント全文
- 出力：以下のJSON形式で回答を返すようプロンプト設計

```json
[
  {
    "id": 1,
    "answer": "回答テキスト",
    "source": "security_policy.pdf - パスワードポリシー章",
    "confidence": 92
  }
]
```

- プロンプト設計のポイント：
  - 必ずドキュメント内の根拠箇所を引用すること
  - 根拠が見つからない場合は confidence を低く（50以下）設定すること
  - 回答は日本語で簡潔に記述すること
- テスト：1問だけで呼び出し、JSONが正しく返るか確認

### STEP 2-5｜Excel出力モジュール（excel_writer.py）
- 元の質問Excelに以下の列を追記して保存
- `回答` | `根拠ドキュメント` | `信頼度スコア` | `フラグ（🚩）` | `担当者コメント`
- フラグ条件：`confidence < 80` → 🚩、セルを赤ハイライト
- テスト：ダミーJSONを渡してExcelが正しく出力されるか確認

### STEP 2-6｜FastAPI エンドポイント構築（main.py）
- `POST /run` ：Excelアップロード → 回答JSON生成 → レスポンス返却
- `POST /export` ：承認済み回答JSON → Excel出力
- テスト：`curl` or Postman でAPIの疎通確認

## PHASE 3 ── フロントエンド実装（レビューUI）

> ゴール：ブラウザ上で回答を確認・修正・承認できるUIを動かす

### STEP 3-1｜React プロジェクトセットアップ
- `create-react-app` or `Vite` で初期化
- バックエンドAPIとの接続設定（CORS対応）

### STEP 3-2｜レビュー画面の実装
- 質問ごとにカード表示
- 表示項目：質問テキスト、AI回答（編集可テキストエリア）、根拠ドキュメント、信頼度スコア
- フラグ：`confidence < 80` → 🚩バッジ表示 + カードを赤枠ハイライト
- アクション：承認ボタン / 保留ボタン

### STEP 3-3｜Excel出力ボタンの実装
- 「出力」ボタン押下 → 承認済み回答を `POST /export` に送信 → Excelダウンロード

## PHASE 4 ── 結合・動作確認テスト

> ゴール：PHASE 1 のテストデータを使い、エンド・ツー・エンドで動作を確認する

### STEP 4-1｜E2Eテストシナリオの実行

| # | テストシナリオ | 確認ポイント |
|---|---|---|
| T-01 | 質問Excelをアップロード → 回答生成 | 全質問に回答が生成されるか |
| T-02 | 高信頼度の質問 | confidence ≥ 80、フラグなし |
| T-03 | 低信頼度の質問（根拠なし） | confidence < 80、🚩フラグが出るか |
| T-04 | 回答を手動修正 → 承認 | 修正内容がExcelに反映されるか |
| T-05 | Excel出力 | 全列・フォーマットが正しいか |

### STEP 4-2｜不具合修正・回答品質チューニング
- プロンプトの調整（根拠引用精度・信頼度スコアの適切さ）
- 出力ExcelのUI調整
