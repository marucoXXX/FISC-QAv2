## テスト前準備

```bash
# 1. サービス起動
./scripts/dev.sh start

# 2. DBクリーン（必要に応じて）
sqlite3 fisc_review.db "DELETE FROM session_questions; DELETE FROM sessions; DELETE FROM past_qa; DELETE FROM common_answers;"

# 3. DBマイグレーション実行
python3 -c "from src.web.db import init_db; init_db()"

# 4. 差分テストデータ生成（A8,B5で使用）
# → テストA2完了後に実行（過去回答が必要なため）
```

## テスト一覧（20パターン）

### A. ワークフロー基本フロー

---

### A1: XLSX freetext形式で全5ステップ完走

**目的**: クラウドチェックリスト（XLSX, freetext）でワークフローが最後まで動作すること

**前提条件**:
- 金融機関「テスト銀行A」が登録済み
- QAファイル設定: format=xlsx, question_col=D, answer_col=F, data_start_row=14

**手順**:
1. ワークフロー → 新規ワークフロー
2. 銀行=テスト銀行A、アンケート=クラウドチェックリスト を選択
3. `2025年クラウドチェックリスト.xlsx` をアップロード
4. 質問が抽出されることを確認（__件）
5. Step2: マッチング実行 → 結果を確認 → 確定してStep3へ
6. Step3: マッチング実行 → 結果を確認 → 確定してStep4へ
7. Step4: 生成開始 → 完了まで待機
8. Step5: 回答一覧を確認 → エクスポート

**期待結果**:
- [ ] 質問が正しく抽出される
- [ ] 各ステップで画面遷移できる
- [ ] Step5で全問に何らかの回答がある
- [ ] エクスポートしたXLSXのF列に回答が記入されている

---

### A2: DOCX assessment形式で全5ステップ完走

**目的**: 安全管理措置アンケート（DOCX, assessment）でワークフローが動作すること

**前提条件**:
- 金融機関「SBI新生銀行」が登録済み
- QAファイル設定: format=docx, question_col=A, answer_col=D, choices_col=B, remarks_col=E, table_index=1, format_type=assessment

**手順**:
1. ワークフロー → 新規ワークフロー
2. 銀行=SBI新生銀行、アンケート=安全管理措置実施状況確認表等 を選択
3. `01_安全管理措置アンケート.docx` をアップロード
4. 質問が抽出されることを確認（~48件）
5. Step2〜Step5を順に実行
6. Step5で「確定して蓄積」を押す

**期待結果**:
- [ ] DOCXから質問が正しく抽出される（48件程度）
- [ ] Step5で○/△/×判定が表示される
- [ ] 「確定して蓄積」後、過去回答DBに蓄積される
- [ ] エクスポートしたDOCXのB列に○/△/×、D列に回答が記入されている

### A4: 過去回答が全問マッチ→Step3/4スキップ

**前提条件**:

4. 全て採用 → Step3へ

6. Step4: 「生成が必要な質問はありません」でスキップ
7. Step5: 全問が「過去回答」ソースであること

**期待結果**:
- [ ] Step2で全問マッチ（マッチ率100%）
- [ ] Step3がスキップされる
- [ ] Step4がスキップされる
- [ ] Step5で全問のソースが「過去回答」

**期待結果**:

### A8: Step2で一部採用・一部不採用

**目的**: 差分の大小に基づいてユーザが採用/不採用を判断できること

**前提条件**:
- テストA2完了後に差分テストデータを生成
  ```bash
  python3 scripts/generate_diff_test_data.py
  ```

**手順**:
1. 安全管理措置アンケートで新規ワークフロー作成
2. Step2: マッチング実行
3. 各カードの差分表示を確認:
   - Q1-Q8（完全一致）→ 「差分なし」→ 採用
   - Q9-Q16（微小差分）→ わずかなハイライト → 採用
   - Q17-Q24（小差分）→ 数語ハイライト → 採用判断
   - Q25-Q32（中差分）→ 多数ハイライト → 不採用判断
   - Q41-Q48（マッチなし）→ 過去回答なし表示
4. 採用/不採用を選択して確定

**期待結果**:
- [ ] 差分なしは「差分なし」と表示
- [ ] 微小差分は1-2文字だけハイライト
- [ ] 中〜大差分は多くの箇所がハイライト
- [ ] 採用した質問は「過去回答」、不採用は次ステップへ

### B. 回答品質

---

### B1: AI生成回答に根拠（ソース参照）が付与されているか

**目的**: ハルシネーション防止のため、回答に必ず根拠が含まれること

**前提条件**: テストA6の結果を使用

**確認手順**:
1. Step5の各カードで「参照:」欄を確認
2. 参照に具体的なファイル名・セクション名が記載されていること

**期待結果**:
- [ ] AI生成の回答に「参照: xxx.pdf」等の根拠が付与されている
- [ ] 根拠のないAI生成回答がないこと

---

### B2: KB文書に記載がない質問にハルシネーションしないか

**目的**: KBに該当情報がない場合、「回答不可」等になること

**確認手順**:
1. KB文書にない分野（例: 暗号通貨取引規制）の質問があった場合の回答を確認
2. confidence=low や「回答不可候補」のステータスになっていること

**期待結果**:
- [ ] KB未記載の質問に対して、もっともらしい嘘の回答をしていない
- [ ] 回答不可・低確信度の表示がある

---

### B3: 複数のKB文書にまたがる質問への回答

**目的**: 単一文書では回答できない質問に複数ソースから回答できること

**確認手順**:
1. 「バックアップとDR対応」のような複合的な質問への回答を確認
2. 参照に複数のファイルが挙げられていること

**期待結果**:
- [ ] 参照に2つ以上のKBファイルが含まれる回答がある

---

### B4: assessment形式で○/△/×が正しく判定されるか

**目的**: 対策の実施状況が正しく○/△/×に分類されること

**前提条件**: テストA2の結果を使用

**確認手順**:
1. Step5の各カードで○/△/×バッジを確認
2. 回答内容と判定の整合性を確認:
   - 「実施している」系の回答 → ○
   - 「一部実施/検討中」系 → △
   - 「未実施」系 → ×

**期待結果**:
- [ ] ○/△/×が全問に付与されている
- [ ] 回答内容と判定が概ね整合している

## テスト実施順序（推奨）

依存関係を考慮した実施順序:

```
Phase 1: 基盤確認
  E1相当: 金融機関・QAファイル設定を確認/修正
  共通回答DBにcommon_answers.jsonを投入
  KBフォルダの設定確認

Phase 2: フォーマット確認
  C1 → A1: XLSX freetext（クラウドチェックリスト）
  C2 → A2: DOCX assessment（安全管理措置アンケート）
  C3: XLSX非標準（システムリスク評価表）

Phase 3: 回答品質
  A6: 全問AI生成 → B1, B2, B3 を同時確認
  B4: assessment ○/△/× → C4: エクスポート確認
  B10: 3ファイルのエクスポート確認

Phase 4: 蓄積・再利用
  D2: 蓄積された過去回答の再利用
  A4 + D5: 全問マッチ + 工数削減効果

Phase 5: 差分・混在
  差分テストデータ生成: python3 scripts/generate_diff_test_data.py
  A8 + B5: 差分表示確認 + 採用/不採用判断
  A7 + B8: 混在パターン + 共通回答マッチ確認

Phase 6: 大規模
  C10: 100問規模の正常動作
```
